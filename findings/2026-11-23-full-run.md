## False positives: generated equation lemmas

These names are not in the RH source. Lean generates equation lemmas for a definition on demand,
in the first module that unfolds it (with `simp [f]`, `unfold f`, `rw [f]`), so these Mathlib
definitions got their `eq_1` / `eq_def` generated inside RH modules. They equal Mathlib's own
`_apply` lemmas, but there is nothing to remove.

| generated lemma | equal to | found in |
|---|---|---|
| `Finsupp.prod.eq_def` | `Finsupp.prod.eq_1` | 1 module |
| `Function.curry.eq_1` | `Function.curry_apply` | 1 module |
| `Function.prod.eq_1` | `Function.prod_apply` | 5 modules |
| `Pi.map.eq_1` | `Pi.map_apply` | 3 modules |
| `Submodule.spanFinrank.eq_def` | `Submodule.spanFinrank.eq_1` | 1 module |
| `numDerangements.eq_1` | `numDerangements_zero` | 1 module |
| `numDerangements.eq_2` | `numDerangements_one` | 1 module |

`FindDups.lean` should skip a theorem whose name is `<c>.eq_<n>`, `<c>.eq_def` or `<c>.eq_unfold`
when `<c>` is a library constant.
